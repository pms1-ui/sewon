1. 배경 및 목적

세원 WMS 1차 개발 및 내부 연동 개발 진행 중.

ERP 데이터를 추가 연동하여 WMS·ERP 양쪽을 통합 호출·조합하고, AI 기반 분석을 수행한다.

상품·주문·발주·재고 데이터를 하나의 흐름으로 연결하여 의사결정 인사이트를 도출하는 것이 목표.

  • 상품 분석 — 브랜드·카테고리·시즌·원가 기반 수익성 분석. 마크업률, 시즌별 판매 추이, 카테고리 구성비, 재고 대비 판매 효율 파악. 상품 기획 및 발주 의사결정 지원.
  • 통합 매출대사 — WMS 출고수량 × ERP 실판매금액을 주문번호 기준 매칭하여 매출 정합성 검증. PG사 정산서 교차 대조 포함.
  • 발주 관리 일원화 — ERP 발주 데이터를 그대로 가져와 현황 표시. 수기 이중입력 해소. 발주→입고→판매 라이프사이클 추적.
핵심 : WMS에서는 수량·물류 흐름을 확보 중. ERP에서는 금액·상품속성·주문 데이터가 필요.
WMS와 ERP 데이터는 품번(STYLE NO), 온라인주문번호, 셀릭번호 등 공통 키로 내부 조합하여 사용.
SKU 구성 : STYLE NO + 색상코드(3자리 영문, 예 : OTM) + 사이즈코드(예 : 150) = SKU (상품 최소 관리 단위).
WMS 전표번호 예시 : 1000HR251BPT02OTM150 (회사코드 + 품번 + 색상코드 + 사이즈코드). 회사코드(1000) 부분은 무시.

4. 신규 개발 요청

#항목내용비고
1발주번호 채번• 현재 발주번호 필드가 비어 있음.
• 브랜드별 채번 규칙을 정의해서 전달드리면, 그 규칙대로 자동 채번이 가능한지?		STYLE NO + 차수 조합 대체 가능 여부도 확인
2판매예정일 필드 추가 신규• 상품정보등록에 "판매예정일(발매개시예정일)" 입력 필드 추가 요청.
• 단순 필드 추가뿐 아니라 상태 전환 시 validation 로직 필요 :
• 발주확정 전환 시 필수 입력 (월 단위도 OK). 의사결정자(MD/영업)가 입력하는 시점.
• 이후 진행중/입고완료 단계에서는 수정 가능 (확정일로 보정)		내부에서 수정 가능 + 변경 시 로그
3품목별주문번호 키 추가 신규• 현재 WMS에는 주문번호(ORDER_NO)만 있고 품목별주문번호가 없음.
• 세원 셀릭 쪽에서 먼저 품목별주문번호를 생성·전달해줘야 ERP/WMS 양쪽에서 받을 수 있는 구조로 보임.
• ERP와 WMS 각각에 품목별주문번호 필드 추가가 필요.		품목 단위 출고↔주문 매칭. ERP/WMS 동시 반영.
4엑셀업로드 양식 수정 중요• 상품 엑셀업로드 양식을 라인시트 등으로 활용 예정.
• 요청드리는 필드 구성대로 양식 수정이 가능한지?		필드 추가/삭제/순서 변경 포함

6. 데이터 호출 구조 (개발단 검토)

테이블호출 방식빈도비고
상품 마스터전체 목록 수신일 1회건수 적어 전체 수신 괜찮을 것으로 보임. 변경/추가 건만 수신 가능하면 더 좋음.
판매현황기간 지정 수신 (전일)일 1회건수 많을 수 있으므로 전일치만 받아서 쌓는 방식이 적합할 듯.
발주 정보전체 목록 수신일 1회건수 적어 전체 수신 괜찮을 것으로 보임. 상태 변경 이력은 내부에서 별도 관리.

호출 시점 : 세 테이블 모두 새벽 05:00~06:00 예상. WMS 일마감(05:30~05:40) 이후에 맞추면 양쪽 데이터 정합성을 확보할 수 있지 않을까 생각.

동기화 방식 (확정) : 수정일자 기준 정렬 조회하여 업데이트.
상품 마스터 / 발주 정보는 데이터 변경 시 수정일자가 갱신되는 구조를 전제로, 수정일자 기준으로 조회하여 변경분만 업데이트하는 방식 적용.
